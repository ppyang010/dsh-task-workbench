# 工作区分组上下排序验收记录

## 正确需求与边界

- 版本：0.15.0。拖动工作区组头，或点击组头旁的上、下箭头，在**同一分类内**调整整个分组的上下顺序。
- 移除 0.14.0 误加的工作区分组跨分类移动入口与命令；单张会话已有的跨分类移动保持不变。
- 分组顺序以工作区 ID 识别，各分类独立保存；不修改会话分类、组内卡片顺序、原生工作区或电脑文件，也不自动撤销此前用户手动进行的分类变更。
- 默认按工作区名称排序；已排序分组暂时消失再出现时保留位置，新分组在已排序分组后按名称排列。同名不同工作区 ID 分别排序。
- 排序写入本插件独立存储域，不改变既有关注、点子数据结构；筛选隐藏的分组仍参与排序，未确认工作区或有备注草稿时禁用排序。

## 自动化与真实宿主基础服务

- `pnpm run typecheck`、`pnpm test`、`pnpm run build`、`pnpm run pack:check`、`git diff --check`：通过；141 项测试、0 失败。
- 使用 DSH Core 0.2.2-rc.1 的官方 Cordis、WorkspaceRegistry、Typert Gateway、storageDomain 与合成会话，真实 RPC 验证分组排序、重开后保留、原关注记录和原生工作区不变；旧的整组跨分类命令被拒绝。所有合成数据仅写入本工程 `.artifacts`。
- 覆盖独立分类顺序、暂时不可见分组、重复及无效工作区、两窗口并发冲突、存储失败、慢速旧读取、错误提示与服务恢复。

## 合成页面交互

不连接真实 DSH，使用生产组件与合成会话：

- 上下箭头与同列组头拖拽均可调整分组顺序，所有会话原有分类保持不变。
- 向其他分类拖动组头不生效，也不弹出跨分类确认框；单张卡片原有跨分类拖动仍正常。
- 使用预览专用的会话级合成存储验证刷新后保持；「我的关注」与「等我处理」顺序互不干扰。
- 自动待处理分组消失再出现后，已保存的分组顺序保留；筛选隐藏分组时有提示且排序结果一致。
- 模拟保存失败后顺序不变、错误提示在刷新后保留；备注草稿期间排序控件禁用。
- 1280px 与 430px 布局无页面横向溢出。

## 真实界面范围

安装 0.15.0 后仅重载本插件（`include:ppyang010-dsh-task-workbench`）。在真实 DSH GUI 打开「我的任务工作台」只读核对：

- 组头旁为上移／下移按钮，组头可拖动；未再出现「移动」按钮或跨分类确认框。
- 「我的关注」有多个工作区分组时，首项上移禁用、末项下移禁用，中间项可上下移动；「暂时搁置」同样按列独立显示。
- 页面无错误横幅。未点击排序按钮，也未拖动真实分组，因此用户现有分类与顺序未改。具体排序请由你自行操作确认。
