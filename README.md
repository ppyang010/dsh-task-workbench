# 我的任务工作台 · dsh-task-workbench

面向 DeepSeek Harness 的独立个人工作台插件。首版模块是 **我的关注**：从不同工作区挑出需要跟进的已有会话，按自己的分类整理，随时回到原对话继续聊。

包名：`@ppyang010/dsh-task-workbench`。此插件与社区的 `dsh-taskboard`、`dsh-personal-workbench` 是不同项目，可独立使用。

## 首版功能

- **会话顶部入口**：顶部「工作台」位于子智能体入口之后，点击打开本插件。使用宿主 `conversation.session.header.actions` 槽位，以 `personal-workbench` 入口 ID、`priority: -10` 独立注册。旧个人工作台同时安装时只接管其顶部按钮，侧边栏与数据保持原状；旧插件卸载后本入口继续存在。本插件卸载则由宿主恢复仍在安装的旧入口，不修改其他插件文件。
- **新建会话入口**：顶部「新建会话」优先采用看板筛选的有效工作区，否则沿用 DSH 当前会话的工作区；没有有效工作区则显示原生选择页。通过原生入口准备或复用空白会话，保留已有草稿，不发送消息或启动模型；不自动添加关注，仍遵循自动纳入开关。
- **已有会话手动加入**：读取 DSH 原生会话目录，支持跨工作区搜索、多选和去重；无需重新发送消息或启动模型。
- **我的关注／等我处理／暂时搁置**：拖拽换列、列内排序，并提供分类下拉作为等效操作。
- **修改会话名**：卡片「更多操作 → 修改会话名」预填原名，保存后同步更新 DSH 原生会话列表与标题；取消不保存，失败保留输入可重试。断线、归档或不可用会话禁止改名。
- **卡片备注**：备注属于关注记录，版本冲突时保留正在编辑的内容，避免覆盖其他窗口的修改。
- **原生运行状态**：订阅 DSH 的运行、等待审批/方案确认/回答、完成未读状态。等待回应、完成未读的已关注会话自动显示在「等我处理」，只改变显示位置，原分类、排序和备注不变；处理后回原列。暂时搁置优先，不参与自动归集。
- **打开原对话**：调用 DSH 原生 `uiWorkspace.openSession`；历史、附件、模型和技能仍在原生会话页使用，其他原有输入入口继续可用。
- **已取消关注**：顶部入口显示已移出的记录，支持搜索标题、备注、会话 ID 及工作区筛选；可查看取消时间、原分类和备注，打开原对话或恢复关注。取消关注不停止运行，不移动、归档或删除会话。
- **恢复关注**：新取消记录保留分类、已保存备注、创建时间和排序锚点；原锚点仍在同列则恢复原相对位置，否则放到原分类末尾。恢复与撤销为同一原子操作，避免部分恢复；已取消的会话不会自动纳入，手动恢复后解除排除。
- **历史取消记录**：旧版本仅保存排除 ID，升级后可查看并恢复到「我的关注」，无法补回未保存的备注、时间和原分类；列表明确说明。缺失、归档或不可用会话保留记录且禁止恢复，等待目录重新可用。不提供永久清除、批量操作或自动过期。
- **宿主持久化**：关注关系、顺序、备注、设置和排除名单通过独立 `storageDomain` 保存，不依赖页面 localStorage。

## 紧凑布局

- 标题统计和搜索筛选集中在两行，按面板实际宽度自适应，正文区左右保留 16px。
- 桌面三列填满剩余高度，底部保留 16px；长列表按列独立滚动，顶部和列标题保持可见，卡片不拉伸。窄面板可滚动访问纵向分类。
- 点击卡片「打开对话」按钮或标题打开原会话；「更多操作」提供备注编辑、上移、下移和取消关注。长备注默认显示两行，可展开完整内容；没有备注时不保留空白备注区。
- 分类标题旁的箭头可折叠该列，至少保留一个展开分类。折叠是当前面板的显示状态，不修改关注数据。向折叠列拖入卡片后，会在保存成功后展开目标列。
- 每列按工作区 ID 分组，工作区名称排序；组头显示名称和数量，可独立折叠，折叠仅在当前面板生效。同名不同 ID 不合并，目录缺失记录归入「工作区待确认」。搜索只显示有匹配卡片的组，计数显示匹配数／组内总数。
- 同一工作区内保留人工顺序，上移、下移和拖拽排序只作用于同组。跨分类移动后归入原工作区分组，拖入其他工作区区域也不会改变会话所属工作区。移动、添加和撤销成功后展开对应组。
- 列内可用宽度达到 560px／840px 时，同组分别显示两格／三格卡片，顺序从左到右、从上到下。面板窄于 740px 时改为单列排列分类。
- 顶部帮助入口集中说明自动纳入、分类、排序及原生会话边界。

## 等我处理的自动展示

手动待处理卡片先显示，自动待处理卡片随后按原有顺序显示，每条会话仅出现一次。自动项的分类下拉仍显示原分类：选择「等我处理」可长期保留；选择「暂时搁置」立即暂停归集；选择「我的关注」时，只要仍等待或未读，就继续临时显示在待处理列。

自动项不提供上下移动；设为手动待处理后可排序。拖入待处理列是明确的手动分类操作；排序锚点只使用目标分类的持久化记录。备注草稿跨列保留。断线、目录同步中或原会话不可用时不依据缓存状态自动归集，原分类仍保留。

## 复制名称和 ID

在 DSH 左侧会话列表右键菜单中，「复制 Session ID」下方新增独立菜单项 **复制名称和 ID**。无需开关或先关注会话，也不依赖旧个人工作台插件。

原来的「复制 Session ID」仍只复制 ID。点击新增菜单项会复制右键目标的名称与 ID：

```text
会话名称
session-id
```

名称为空时仅复制 ID 并提示；复制失败不会提示成功。通过宿主 `contextMenus` 注册独立动作，不拦截原生点击、不覆盖图标、不修改原生文件或全局剪贴板函数。卸载时移除该菜单项。0.7.0 的历史开关字段保留兼容读取，但不再影响复制行为。不支持菜单扩展的旧宿主保留原生复制和工作台功能。

## 自动纳入开关

默认关闭。开启后，普通会话开始新一轮时自动加入「我的关注」，旧会话续聊也适用。

| 情况 | 行为 |
| --- | --- |
| 开关关闭 | 只手动添加，已有卡片保留 |
| 开关开启，新会话或旧会话开始新一轮 | 未关注且未排除时新增卡片 |
| 已关注的会话继续运行 | 只更新运行状态，不重复添加、不改分类 |
| 仅打开历史会话查看 | 不纳入 |
| 子代理会话 | 不自动收录 |
| 手动取消关注 | 记录排除，之后自动纳入会跳过；手动重新添加可解除 |
| 运行结束、异常或等待交互 | 分类不变，状态展示跟随 DSH |

不一次性回扫全部历史。已有归档会话、目录尚未就绪或不可兼容格式的会话会显示原因，不会为了打开卡片自动恢复或重建会话。

「完成未读」沿用 DSH 页面内存中的提醒语义：它表示后台一轮结束后尚未查看，并不保证结果正确或任务已完成；刷新页面后是否保留由 DSH 原生状态决定。

## 安装与兼容

首版针对 **DSH Core `0.2.1-rc.2`、Node.js 22.15+**。桌面应用的外壳版本与 Core 版本不是一回事。首版安装包需要包含构建后的 `lib`，不要直接把未构建源码目录当作成品安装。

拿到本项目打包的 `.tgz` 后，在目标 Profile 安装：

```bash
dsh plugin --profile desktop add /绝对路径/ppyang010-dsh-task-workbench-0.7.1.tgz
# Web 用户改为 --profile web
```

是否立即加载取决于宿主的插件重载能力。如入口尚未出现，等现有工作结束后完整退出并重新打开 DSH；不要为了安装中断正在运行的会话。

入口为左侧 **我的任务工作台**，进入后使用「我的关注」模块。卸载时仅移除插件，不清除已保存的关注数据：

```bash
dsh plugin --profile desktop remove @ppyang010/dsh-task-workbench
```

## 数据与边界

- 独立存储域：`ppyang010_task_workbench`。实际文件路径由 DSH 当前存储后端配置决定。
- 保存会话 ID、分类、备注、顺序和设置；不复制聊天正文，不保存凭据，不向外部服务发送数据。
- 客户端使用宿主的认证 RPC；无新增网络监听端口、遥测或模型工具。
- 不注入任务认领、执行、验收等 Agent 指令。
- 运行状态即时订阅宿主；面板显示时每 3 秒同步轻量关注关系，以反映自动纳入和其他窗口操作。后台面板不轮询，重新打开时刷新。
- 多窗口操作由宿主串行处理；备注编辑另外校验卡片版本。

## 从源码开发

```bash
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run build
pnpm run pack:check
pnpm pack
```

项目使用 `pnpm-workspace.yaml` 仅允许 esbuild 安装脚本，不修改全局包管理器策略。客户端由官方 `__ModuleLoader__` 共享 React，不能将另一份 React 打入插件。宿主 Remote 参数名是 RPC 契约，禁止压缩改名。

```bash
# 可选：生成生产组件的离线合成会话验证页
node scripts/build-preview.mjs
# 输出 .artifacts/preview/index.html，可直接用浏览器打开，无需启动服务。

# 可选：验证某个本机已安装 DSH 的真实基础服务
DSH_IMPLEMENTATION_ROOT=/你的/DSH安装目录 node scripts/verify-installed-dsh.mjs
```

离线预览使用同一套生产 React 组件、控制器与数据层，数据为合成会话；不代表真实 DSH GUI 已完成端到端验收。集成脚本使用指定安装版本的 Cordis、Typert、storageDomain 和 JSON 后端，数据只写本工程 `.artifacts`，不连接现用会话。
